# 上下文构建与复用：官方报告复核与展示调整

2026-09-12。原本地 CED 章节改名，仍不提交或推送。复核官方报告摘要、§1、§2.2–2.3、§3.2.1–3.2.2、Figure 2，并对照当前组件与模型。

## 教学主线

Agent 工具调用不断带回新材料。请求的代价分成三件事：读入材料、保留历史、恢复可继续执行的状态。章节先展示这三个问题和资源对照，再展开数据流；40 层拓扑用于解释共享的来源，不能代替问题定义。

## 证据与指标口径

| 问题 | 机制与报告依据 | 可展示的证据 | 对服务指标的意义与限制 |
| --- | --- | --- | --- |
| 未命中缓存时，长输入 Prefill 很贵 | CED，§2.2：Decoder 全局 KV 来自最终 Encoder 输出，局部窗口仍需计算 | 同一 40 层的处理位置数比较；长输入趋近减半，短输入收益减弱，Decode 仍全部执行 | 有利于减少输入成本与 TTFT 的计算部分；不能用位置数比当作 TTFT 或吞吐实测比 |
| 长历史挤占运行中缓存并增加搬运 | CSA2 + FP4，§2.3、§2.4.4、Figure 1 | 官方全局缓存 3514 → 890 B/token；等全局缓存预算约 3.95 倍 Token 容量 | 是容量空间与完整历史传输字节收益，不能直接宣称 4 倍并发或扩展模型的上下文上限 |
| 旧会话局部状态丢失，精确恢复代价高 | Encoder SWA Bounded Replay，§3.2 | 全局命中、局部未命中 → 最近窗口重放 → 处理新输入；与精确恢复尾段上界对照 | 减轻恢复负担；需测恢复耗时、命中率和任务成功率。重放为近似，非数值等价 |
| 长期留存局部状态占 SSD | 持久化策略 + CSA2 + FP4，§3.2.1 | 同工作负载持久化大小约为原来的 1/8；局部窗口改由短 TTL DRAM 承接 | 是组合收益，不能单独归功于 CED，也不是所有部署都自动达到的比例 |

报告 Figure 2 的长上下文计算增长是精度加权 FLOPs，4K 到 1M 增长约 25%。归因于联合架构优化，既不等于实际逐 Token 时延，也不能归因于 CED 单项。检索报告全文的 TTFT / latency / throughput 等段落，没有找到能在相同硬件、负载、延迟约束下直接用于本交互页的统一服务加速系数，因此页面不编造毫秒或 tokens/s。

8B Prefill / 16B Decode 是同一 V4.1 模型的激活参数口径，不是 V4 与 V4.1 的比较，也不是请求显存。模型支持 1M 上下文是能力事实，缓存压缩提供资源余量但不自动扩展训练或服务配置允许的上限。

## 本次落地

- 中文标题与入口为“上下文构建与复用”，英文 Context Construction & Reuse / Context Reuse；CED 在内部原理首次出现时解释全称。
- 首屏三个收益同屏显示，明确参照、单位、下降方向与测量边界。整块可点击，在同一区域展示问题原因、输入输出关系和业务含义。
- Token 数与 Prefill/Decode 控制移至总览，共同驱动位置数对照和原有结构、矩阵及字节账本。静态官方报告数字标明基准范围，不随输入伪造变化。
- 原来的层点击、来源追踪、记录选择、全局/局部矩阵保留。没有将协同机制改成互斥算法。
- 局部恢复案例使用已有历史长度作缓存前缀示例；不是完整服务缓存模拟器，不模拟 TTL 演变或命中率。

## 后续完善顺序

1. 请求级流程：显式输入已命中前缀与新增后缀，联动展示首次读取、连续工具调用、旧会话恢复。当前首屏覆盖原因与局部恢复案例，不冒充完整多轮模拟。
