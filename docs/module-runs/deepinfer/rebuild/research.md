# DeepInfer 本次解释合同与取证

主问题是：在输入/生成延迟约束下，为什么同样算力能完成更多有用工作，什么时候能转成单位成本下降。技术依据详见 [primary-checks.md](primary-checks.md)，DeepInfer 固定提交 553741557a57df44a46fb3ab72b6aafeaf945337，DeepGEMM 固定 gitlink 1fc9c66975ee322d628b3288534ca0e9ce12a64d。原始取证早于最终快照；最终再核对了取证与可见机制的一致性。

本章按整套服务→历史/P/D/服务资源→MoE 内核或 CPU/GPU 配合组织。缓存实验沿 R 的同一 H/N 块移动；Prefill 沿未命中后缀连接 CED 共享块 KV；Decode 中 T1 连接 R，内核 A/B/C 保留该批 T 编号。静态 CED 图只讲该模型能力如何减少工作，细节去 Cache Architecture；DSpark 只在 Decode 的相关专题入口展开。量化、并行策略亦保留专题边界。

最终可执行示意采用 8 卡、8 等大逻辑专家、top-1，每卡1或4个 Token；这是对 primary-checks 中建议模型的具体化，未照搬其64-token/top-2备选。直接数真实路由列表的激活 (rank, expert-copy)，不把权重份数当真实 HBM 字节或速度比。24缓存阶段案例、64专家快照和依赖/资源守恒均有纯模型检查。热点副本改善最忙卡工作量但增加副本/读取；低负载下EP2/EP8均为8份，不能无条件推倍率。

Mega MoE 图保留输入、权重、对称内存缓冲、输出与必要通信；按块依赖及通信/计算资源不冲突。12/8是示意时长；基线是整批阶段屏障，不声称真实分离实现完全不重叠。P/D图固定两份抽象资源和12工作量，示意D更早、P更晚，未把分离当凭空省卡。CPU/GPU图仍保留上一采样→下一前向依赖。
