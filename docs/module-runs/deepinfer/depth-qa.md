## Practical limits

The framework was studied statically, not executed on GPU/NPU. External vendor submodule contents were absent; call contracts and in-repository TileLang code support the explanation, not an invented internal tile/warp/SASS animation. Production storage/routing is documentation evidence. Toy allocation, byte accounting and timeline units are not measured throughput, model-quality validation or full service simulation. Several mechanisms intentionally remain source-backed inspectors rather than interactive numerical simulators. System's other OS branch remains untested. The machine run validator checks evidence bookkeeping; it cannot prove teaching quality or prevent every future content omission.

The independent skill evaluator performed two decision dry runs, not a second implementation/E2E benchmark. Multi-root, output-path and old theme wording ambiguities it identified were clarified in the project adapter/AGENTS. No broad one-shot success rate is claimed from this case.
