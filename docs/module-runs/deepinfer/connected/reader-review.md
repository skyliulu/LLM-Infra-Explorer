## 放下页面后能给出的解释

输入和逐步生成的批量不同，所以 P/D 不用同一种并行规模。Attention 随本卡请求读历史；MoE 把输入按专家聚集后再返回原卡。宽 EP 将多个小组对同一专家的输入汇到一份权重上：输入矩阵的行数增加，权重形状和总专家计算并没有缩小。足够并发时可以减少重复读权重；低并发时这个优势消失，热点还可能让全组等最忙卡，需要用额外副本换负载分散。

聚集后的输入仍要分发、计算、合并。块级就绪允许一个块回传时另一个计算，减少整批阶段等待，不能越过同块的生产/消费依赖，也没有消除 HBM 缓冲或通信。输入侧共享历史减少重算，并让请求不必回到上次计算的机器；存储和搬运要付费用。P 用时间预算、D 用请求数和 KV 总量分配剩余工作，CPU/GPU 交叠补充另一层等待。

这些机制解释收益来源，性能是否兑现仍要看给定条件下的曲线。固定服务速度要求，比较满足要求的有效吞吐，再将完整资源费用摊到输出；不能把理想权重读份数当成速度倍率，更不能从生产收入直接算利润和回本。并发少、热点重、互联跟不上或缓存命中低，都可能减弱这些收益。
