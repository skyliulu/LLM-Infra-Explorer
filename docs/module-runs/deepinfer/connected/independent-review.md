- 将每 rank 批量改成 1，读取两侧相同的活跃权重数和总计算量。再改为批量 4、热点路由，关闭/打开热点副本，观察忙卡负载下降和权重副本增加的代价。

## 读后可重建的解释

DeepInfer 先按 Prefill 与 Decode 的不同工作负载分开资源池。Attention 的历史仍在请求所属 rank 上读取，MoE 则把输入按专家重组，再把结果送回来源。Decode 每个请求每步贡献的 Token 少，宽 EP 可以把更多输入行汇到同一份专家权重上，减少多个小组重复读取同一专家的机会；计算总量并没有随之消失。

这种布局要有足够并发，也会遇到热门专家和通信等待。页面允许看到低批量时权重读取优势消失，热点时忙卡反而成为限制，以及增加物理副本怎样用显存换取负载分散。内核部分把输入缓冲、专家计算、输出缓冲和来源 rank 分开，按块就绪后推进，说明融合为什么可以减少整批阶段等待，同时保留真实的生产/消费依赖。

输入侧通过共享块 KV 少做重算，并把计算路由与历史所在机器解耦；代价是存储和搬运。调度再用 P 的时间预算、D 的请求数和 KV 总量分配工作。最后必须回到实际服务目标下的吞吐曲线；理想权重读份数不能替代测量，也不能与其他示意收益相乘。单位费用由满足目标的有效输出量和完整资源费用共同决定。生产收入本身不能推出利润或回本周期。

这条解释能从页面本身得到。若并发太少、路由过热、通信跟不上，或缓存命中低，局部收益就未必转化为预期的端到端优势；当前页面已有相应边界，不需要审阅者补入未展示的推理。
