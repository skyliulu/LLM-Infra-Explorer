使用独立 IAB 标签，实际打开开发预览 http://127.0.0.1:5173/#deepinfer，中文、浅色、桌面约1280宽。Edge 不可用，改用新 IAB 标签；没有调整 owner 的主题或尺寸。先读完整默认渲染内容，再依次定位并看实际截图：开篇/目录/并行布局 → Wide-EP 正文和专家输入批量 → Mega MoE 正文与按块时间轴 → 共享缓存正文/状态表/前缀实验 → 调度正文与CPU/GPU实验 → 成本全文和官方曲线 → 页尾。打开了内核、缓存、CPU/GPU和官方图等折叠内容。

实际操作包括：专家EP8改EP2，选中专家输入行数随模型变化；每卡输入改1后EP2/EP8读取均为8份；内核沿相同配置显示T1–T8分成三个块，时刻3可见A合并回传与B计算；缓存改3块命中后显示H1–H3与H4–N2补算边界；CPU/GPU显示同步24与异步18的明确示意时间；官方图成功加载，坐标为单用户速度与每GPU输出吞吐，并带固定上下文/接受条件。

## 技术论证能否从页面重建

现在不操作任何可选实验也能读到完整论证。开头从Prefill/Decode的每轮Token量差异出发，解释为什么Prefill采用较小EP/DP而Decode采用Wide-EP；随后说明Attention按请求DP、MoE按专家EP的层内切换。Wide-EP不是只给“访存减少”结论：正文把跨独立组重复权重读取与专家GEMM的Token行数m联系起来，并明确k/n不因扩大EP缩小。然后由新增通信与热点尾部引出EPLB和Mega MoE；内核段解释两次GEMM、SwiGLU、分块生产消费、对称内存及必要通信。共享缓存段从prefix affinity与负载路由冲突出发，分别交代3FS块KV、主机SWA、GDR分层装入和CED重放接口。调度段给出Prefill时间quota/二次成本模型/组内MIN、Decode请求数与KV长度两个负载量，最后才讨论离线曲线、SLO与成本。

这些内容足以让有基础的技术读者预测三个边界：低并发下Wide-EP不再显著摊薄读取；热点路由仍会拖慢整批且副本要付显存代价；共享缓存读得回来不代表元数据匹配或搬运免费。相比原先“总览直接到结论、推理藏在替换view”的组织，改进发生在真实默认阅读路径，而非仅增加一段过渡。

一手核对使用本地固定DeepInfer提交553741557a57df44a46fb3ab72b6aafeaf945337的inference_deployment_qa.md：EP/DP部署、Attention DP、EPLB副本、3FS与SWA存储区别、匹配/异步fetch/GDR、Prefill quota和Decode双指标均与该文一致。Mega MoE与理想时间轴仍是有边界的说明；本审查没有GPU性能复现，也没有逐行审核DeepGEMM内核。

## 发现与复核

1. 初始集成将meta字段当顶级读取，标题/lead会空白；作者修复后，实际首屏已显示完整标题与引言。
2. 初始sections自带编号而renderer重复显示编号；实际目录与正文现每处只显示一组编号。
3. 调度实验标题曾承诺阶段资源延迟取舍，实际只包含CPU/GPU；已改为“引擎内CPU/GPU交叠”，实际UI确认。
4. 迁入文章的旧实验仍提到不存在的“请求R”和“上一层”；已改成自足的同批请求说明与“按上节相同配置”的块映射，实际DOM再次确认。
5. 页尾曾写“以下示意实验”，但已到结尾；已改“本文的示意实验”，实际UI确认。

以上均关闭。当前未发现阻塞性的技术叙述或默认阅读路径问题。中文仍有工程术语和少量承接句，但标题/段落主要承载具体设计判断，不再反复用“先看、再看、继续”指挥读者。密度来自设计理由、接口和约束增加，页面也减少了反复显示大总览的空耗。

## 新规则行为附记：两种章节的验收决策

这是独立情境 dry run，不是新增浏览器执行或对 FlashAttention 现有实现的验收。

**情境 A：技术报告默认只有架构和结论，机制藏在七个替换视图。** 我会拒绝报告的阅读架构验收。局部 QA 能证明单个实验正确、按钮有效，却无法让顺序阅读的读者知道结论如何得出。下一步先写出“负载约束→设计选择→必要机制→新瓶颈/代价”的简短论证，检查实际默认页面是否保留这条链，再将已有实验贴回各自论点旁。不是要求七个面板全部默认展开，也不要求固定字数；如果两三段加一张关联图即可保留推理，就不加长文。修改后重新实读整条路径，不能只补一条“点击查看细节”提示后放行。

**情境 B：FlashAttention 执行图分步显现，缺少长文但能看到归一化保持与 IO 下降。** 我不会因缺少三千字文章判失败，也不会给它补成技术报告。该章的学习对象本来就是执行过程，步进是主路径而非把论证藏进互斥特性标签。下一步实际走完默认执行：追踪同一行的 running max、归一化累积量和输出重缩放，检查结果与标准 Attention 一致；再检查分块矩阵的 SRAM/HBM 所有权与读写计数，改变块大小或序列长度，看 IO 为什么变化。若这些对象、更新依赖和边界在图中有充分标注，配少量解释就可通过教学验收；完整交互/主题等必需检查仍须执行。只有当图仅亮阶段名、数字自行变小而看不到重缩放或数据搬运时，才修具体机制表示，仍不以补长文代替。

判断差异来自读者实际经过的因果路径和学习对象，不能用“有没有长文章”作统一门槛。此次规则更新应拦住 A 的假通过，同时允许 B 保留以执行图为主的合适形式。
