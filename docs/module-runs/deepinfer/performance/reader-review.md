本轮任务仅评审。用户要求主 agent 亲自从上到下通读，判断实际效果是否符合此前提出的要求。没有修改页面实现或 Skill，没有重新生成页面，没有增加测试矩阵，也没有委派他人代读。

## 结论

**尚未达到“层次清楚、深入浅出，让读者看完知道 DeepInfer 为什么快、为什么省”的整体要求。** 浅色主题、配置操作、部分示意和来源口径有改善，原来的功能检查仍有价值；但上一轮把这些通过外推成整章教学效果达标，判断过早。撤回无剩余教学 P2 的整体结论。

## 实际阅读与操作

在生产预览 `http://127.0.0.1:4173/#deepinfer`，使用当前中文、浅色、实际桌面窗口：

1. 逐段读首屏的标题、生产数字、限制说明、总问题与单位成本公式。
2. 读主架构的全部节点与箭头；依次打开缓存、Prefill、Decode 分支，通读每段文字、图例和限制。
3. 切换流量方向与 EP2/EP8，查看分组、权重计数、热点均衡和内核段落；展开官方对照图，读图注。
4. 继续读经济假设、三个滑杆、默认回收期与30天说明。
5. 展开引擎，读队列/调度/执行/状态图；进入设备执行，逐项读专家与采样说明，再返回“推理服务”。
6. 将请求演示从等待依次推进到调度、模型执行、采样和更新，逐步阅读说明；再读同步/异步时间图、条件、来源与页尾。
7. 恢复通读前的主要选择、预算/成本、暂停进度和展开状态。没有开启自动播放。

## 按阅读顺序发现的问题

### 1. 首屏提出了主题，但尚未建立解释所需的起点

生产数字、说明、总问题、成本恒等关系依次出现。读者还没形成“什么工作负载造成哪些主要开销”的认识，就已经看到了结果和很多限制。少算、每轮高效、少等能归纳收益，但它们还不足以说明本框架的设计取舍与辨识度。需要建立问题和约束，而不仅是补一句中心问题。

### 2. 主架构的选择与讲解层级不一致（P2）

点选 Prefill 后，段落同时讲跨阶段资源配置、引擎异步安排及 DSpark。后两者不能由“正在展开 Prefill”这个位置自然推导。上层按组件选，下面按收益类别写，导航与论证采用了不同分类。

主图的整体为 Prefill→Decode＋共享存储；底部“继续下钻”又开启队列→调度→执行→状态的另一套图。其“返回上层”通向服务入口→通用引擎↔历史缓存，没有清楚映射回上方 P/D 实例。两个局部图分别合理，却没有组成一条连续的总览→组件→机制路径。

证据：`reader-review-evidence/prefill-scope.jpg`；上述实际下钻和返回操作。

### 3. 多个交互展示了结论或预设，机制仍依靠正文（P2）

- 缓存滑杆表示1000输入位置有多少可以复用；没有出现历史如何被命中、读取、交给 Prefill 或跳过重算的可追踪对象。它帮助计数，尚未表现框架的缓存/路由组织。
- 资源分配把流量预设映射到2:6/6:2；没有显示混在一起时哪里等待、拆开后哪种等待被消除，读者看到的是预设方案变了。
- Wide-EP 比此前有进步：专家分片与权重计数可比较。但图中 Token 仍主要是数字，没有展示汇入专家、同一权重服务多个 Token 的过程。
- 热点均衡条图说明最慢卡拖住整批；专家副本如何改变热点放置尚在文字中。
- 内核段落仍是“分发→专家计算→合并”一行箭头，加库名与融合说明。没有看见分离执行多了什么中间搬运/等待，融合后省了什么。用户此前点名的内核层理解仍较薄。

这些不要求增加全部算法细节或复制别的章节。这里缺的是服务于本章因果解释的最小机制表现。

证据：`reader-review-evidence/kernel-explanation.jpg`，缓存分支与 EP 切换的实际通读。

### 4. 经济测算占据主阅读位置，但没有完成性能到成本的解释（P2）

CAPEX、支出、收入比例的计算有明确假设，不是本轮发现的算术错误。但前面的缓存/并行/等待图并未解释这些设计怎样改变同等服务目标下的资源消耗。读者很容易记住醒目的41.7天，却仍说不清单位推理成本为何降低。

不能将几个示意倍率强行换算成真实财务收益。应先完成有效吞吐、延迟约束与所需资源之间的工程解释，再决定收益测算在主线中的位置。

### 5. 后半页重新开始讲通用引擎，整体收束不足

读完收益部分再展开整套旧引擎演示，主题又回到请求如何推进。请求与异步时间图是目前较具体、较易跟踪的局部演示，但它们没有把前面的缓存、专家和内核重新汇合到开头的问题。页尾直接到源码和相关章节，缺少基于刚才探索形成的完整回答。

### 6. 中文与视觉层级仍需按连续阅读修订（P3）

“少等：按阶段配资源，让各层都跟上”“内核决定每份工作本身要花多久”等句子仍较泛。正文里“不是实测”“示意”“不代表”等说明出现密集，来源与过程性说明多次打断解释。必要条件应保留，但需要安排好主次和阅读位置。

大卡片、段落、图和注意事项相继堆叠，多个标题权重相近。当前浅色图已不再整块固定黑色，这一点不能抹去；但配色合格并不意味着阅读节奏和内容层次合格。

## 对验收方法的反思

先前检查回答了配置是否变化、数字是否守恒、是否溢出、主题是否解析等问题；独立审查也修掉了局部缺口。仍然缺少一次不借助作者意图、沿默认阅读顺序完成的整章理解检查。

本轮不继续加控件或扩写 Skill。下一步应先重建一个连续的讲解结构，明确每一层的问题、该层必须看见的机制以及返回整体后的解释，再决定实现。上述 P2 尚未修复，当前教学验收应保持重新打开状态。
