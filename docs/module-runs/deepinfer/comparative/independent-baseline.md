## 三个 P2 交付问题

1. **结果问题未成为首屏组织轴。** 原先用户反复要求为什么性能高、为什么单位成本低。当前先展示服务组件名，末尾才见实际性能图；中间几节缺一个持续的“当前在解决哪种浪费/约束”的视觉锚点。读者很容易把它读成几个独立示例，虽然可以复述段落，也不等于接受到框架因果主线。
2. **核心视图先指标后对象，不能在合理一屏内完成观察。** EP区别理论正确，但默认指标大表优先、物理副本和输入行在下方；卡片过大、字/对象过小。相对对照章，单位屏幕中真正可辨识的关系少，改变配置后的核心证据不在相同观察中心。应把对象差异摆在视图中心、紧邻小型量尺，避免删技术细节来换“清爽”。
3. **内核依赖有数据，表示仍停留文字状态表。** 当前状态表不是错误，但对“怎样交叠、少等在哪”缺直接几何解释。需要把A/B/C在通信/计算/回传中的时间或轨迹显出来，状态表降为选中块的局部检查证据；不需要做真实SM模拟或虚构测时。

## 优先修改

1. 以“有用输出/资源费用”的问题和一个可追溯官方曲线工作点开始，接紧凑因果架构。把读取重复、等待、重算/分配三类约束映射到既有组件，让主图成为导航和解释骨架，而非另一张静态目录。性能数值必须仍保留来源/条件，不能拿演示32/8推出4倍速度。
2. 让默认每个主实验在一屏中完成“同输入对象→变化→收益与代价→说明”。专家先画输入汇集/副本，选中实际对象直接检查；指标用精简同屏图例/量尺。利用大屏，不要沿用窄居中文章加宽大表格；小屏保留对照的公共量尺。
3. 用稳定身份和空间编码代替状态文字的重复：P/D/存储/专家/通信保持职责颜色，kernel用同尺度时间泳道+就绪游标，所选块显示生产消费状态。加入有目的的下一步/关键事件检查，避免只把滑条扫一遍。正文解释“为什么这样安排”，而不再重复图中每格标签。

不建议照抄其他章固定三栏、增加装饰色或堆更多动画；应借鉴的是对象、比较、反馈与解释的距离，而非外观模板。也不建议再次仅凭12组合截图/构建/无溢出判定教学达到用户要求。
