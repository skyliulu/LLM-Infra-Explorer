# Brief: GPU Execution & CUDA Graph (`gpucudagraph`)

- **Teaching question**: Why does small-batch Decode stall at low GPU utilization despite doing almost no FLOPs, and how do CUDA Graph, Piecewise CUDA Graph, and Operator Fusion each remove a distinct bottleneck (CPU launch latency vs HBM round-trips) while introducing static-shape / padding boundaries?
- **Explanatory thesis**: Small-batch Decode hits two distinct ceilings before GPU Tensor Cores ever saturate: (1) per-kernel CPU host dispatch latency (~12–15 µs/op) exceeds microsecond GPU kernels, starving the GPU stream; (2) unfused elementwise kernels (RMSNorm, RoPE, SiLU*Mul) bounce full `[B, H]`/`[B, F]` activations across HBM. Full CUDA Graph collapses dispatch into one replay launch at the cost of static shapes & batch-bucket padding; Piecewise CUDA Graph (vLLM V1 / SGLang) splits around dynamic Attention; Operator Fusion keeps intermediates in registers/SRAM. The H100/B200 Roofline unifies why faster Tensor Cores raise the ridge point and widen the memory/launch gap at small batch sizes.
- **Chapter ownership**: Owns GPU execution hierarchy, CPU launch wall, CUDA Graph / Piecewise Graph, Operator Fusion HBM traffic, and hardware Roofline. Links to `LLM Inference` for Transformer tensor semantics and `Flash Attention` / `Flash Decode` for tiled attention kernels.
- **Capabilities**: `multiple-modes`, `timeline`, `resource-metrics`, `structural-comparison`, `data-movement`, `math`.
