# DeepInfer 改版经验：从内容齐全到读者能理解

2026-11-13。本记录沉淀本轮已发生的失败、修正和可迁移判断。用户在当前对话明确认可新版比之前明显改善；这是这个案例的反馈，不代表任意主题都能首轮成功。当前任务只更新两套 Skill 和经验记录，不继续改已认可的页面。

## 两套 Skill 各自负责什么

- [analyze-technical-principles](../../../../.agents/skills/analyze-technical-principles/SKILL.md)：确定读者关切和解释主张；按因果关系、组件职责和章节所有权组织内容；交接首个有用观察、默认论证路径、对象/关系及边界预测。
- [develop-interactive-module](../../../../.agents/skills/develop-interactive-module/SKILL.md)：将上述关系映射为页面和交互；落实直接对象选择、图与量贴近、适合关系的空间/时间表达；实施真实主题/屏宽检查、owner完整阅读和独立结果复核。

两者通过渲染 Skill 的 technical-analysis.md 交接，避免分析止于目录、渲染重新拿现成控件决定主题。内容正确、工程可用、读者好学是不同判断，均需要对应证据。

## 可复用的分析到渲染交接

每个关键机制只需说清以下关系，不要求机械增加文件或固定面板数：

1. 读者当前要解释什么结果或约束；证据是什么，适用条件是什么。
2. 要追踪哪个具体对象和输入；对照中哪些事实必须保持相同。
3. 发生什么变换、移动、等待、复用或决策；这是空间、时间、所有权还是数量关系。
4. 资源使用为什么改变，付出什么代价，在哪个边界收益减弱。
5. 页面要让读者实际看到什么、操作后能预测什么；如何返回它的父问题。

默认阅读路径保留论证，局部交互提供内部证据。二者都不能由作者脑内补齐。一个读者能预测“低并发省不下重复读取”“输入未就绪不能计算”“短长请求可能选不同接收卡”，比记住优化名称更能证明理解。

## 不推广成固定模板的部分

三处优化卡、六节正文、EP2/EP8、A/B/C、某种配色和像素高度，是本次表示选择。固定状态的递归算法可能用一个状态容器和一次更新就够；没有测量时用具体约束进入，不编造指标；小修保留原布局并做有边界的验收。借鉴的是关系与反馈距离，不是邻章外观。

性能图、演示计数和经济口径继续区分。理想读取下降不是实测速度倍率；固定请求数不是固定用户速度；生产收入不是利润或回本。研究完整不要求全部展示，限定语也不能代替必要机制。

## 由浅入深与真实实现

用户随后明确补充：正确性必须保证，深入后应尽可能与真实实现一致。因此把原来的“有疑点时按需读源码”加强为按断言类型取证：论文支撑算法和数学，架构文档支撑系统设计，实际形状/精度/布局、分配/归属、生命周期、调度、缓冲/同步等实现断言必须核对匹配版本的活动源码路径。

浅层缩小尺寸、抽样通道或省略次要工作，可以降低认知负担；不能改错数值含义、数据归属和依赖。深层需把相同对象映射到真实布局/算子/读写和提交操作，注明与示例的差别。Prefill/Decode、CPU参考/CUDA内核、不同后端和模型版本不能拼成一条虚构路径。

新增共同规范 [implementation-fidelity.md](../../../../.agents/skills/develop-interactive-module/references/implementation-fidelity.md)，两份Skill入口和交接/内容/验收参考均已接入：固定版本源码→真实运行事实→纯模型→页面对象/公式/指标，逐项核对；用独立计算、参考例程或上游测试等验证关键结果和边界。自洽测试、注释和引用链接均不能单独证明正确。源码本身也可能有bug，应报告与算法规范的差别，而不是照搬成原理。

源码核对是后台分析手段，是否显示代码由教学需要决定；不把章节改成目录或API讲解。缺源码、缺上下文、没有硬件执行证据时如实保留未验证项；关键实现不一致阻断技术通过。已有章节不会因为规则更新而自动获得“已按源码验证”的标记，本次也未做全站源代码正确性审计。
