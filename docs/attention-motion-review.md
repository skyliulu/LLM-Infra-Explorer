# Sparse Attention / DeepSeek CED 动态展示评估

2026-09-12。本轮只评估，不修改模块行为、不提交推送。

## 现状判断

源码与浏览器交互检查一致：Sparse Attention 的状态是参数、Query、焦点与追踪记录，切换 Query 后直接重算最终选择/数值；DeepSeek CED 的阶段是 Prefill/Decode 场景选择，技术节点点击切换解释。两者有交互，但没有可暂停/单步检查的执行进度、缓存写入过程或读取累计。ResizeObserver、布局效果或CSS过渡不等于算法过程演示。

此前优先建立静态架构与数值联动是合理的第一步；但这两个主题都包含会影响理解的执行依赖，因此缺少过程展示已经形成教学缺口。动态应补充现有画布，而不是另起一套页面或把结构说明强制改成逐页播放。

## 建议实施顺序

| 顺序 | 过程 | 可见变化与学习目标 |
| --- | --- | --- |
| 1 | Sparse Attention：执行一次 Query | Query 投影 → 索引打分及 Top-K（仅存在索引器的模式）→ 选中记录被读取 → 与适用的局部窗口合并打分/归一化 → 输出。记录ID和原矩阵保持，区分已驻留、被选中、已读取。换Query保留历史缓存。 |
| 2 | DeepSeek CED：一次 Prefill / Decode | Prefill 分块处理输入、H20就绪、全局KV投影写入、尾部位置进入Decoder并逐层构建局部状态、状态备齐；Decode只推进当前位置、遍历40层、追加新KV。全过程保留同一分叉图和检查面板。 |
| 3 | 缓存随位置增长 | Sparse模式按自身压缩规则展示暂存、记录发布、局部窗口移出；CED展示共享缓存只创建一份，Reindex和Reuse读取相同对象。写入后才增加已驻留容量，不把每次读当成新分配。 |
| 4 | 会话恢复 | 已命中全局前缀、局部状态缺失 → 有限重放 → 局部状态恢复 → 新后缀继续。需要新增明确的命中前缀/未命中后缀和缓存生命周期模型后再制作，不能用滑动高亮伪装真实恢复。 |

HCA 不应添加虚构 Top-K 阶段；有无局部支路由当前模型决定。CSA压缩源范围遵从现有重叠分组语义。CED不得把共享KV画成20份副本，也不得把Prefill减少工作扩展为Decode跳过后半层。播放时长表示教学节奏，不能表示GPU延迟；图中的依赖先后不宣称内核的实际调度顺序。

## 交互约束

- 保留当前总览、矩阵、选中行、缩放拓扑、业务收益与下钻路径；在受影响画布旁增加播放/暂停/单步/重播。
- 默认仍可直接检查完整结构，主动播放时才进入过程状态；不打开页面就循环闪烁。
- 执行阶段与用户选中的检查对象是两种独立状态。点击部件不能暗中推进计算或跳过依赖；提供可选的跟随执行位置。
- 同一派生模型控制已就绪张量、活动连线、读取累计、容量、公式和解释；避免只有发光箭头，全部输出却早已显示成已完成。
- 容量、单次预计读取量、当前累计读取量要清楚区分。最终静态数值可保留作目标参照，不能与过程中已经发生的量混为一谈。
- 中途改算法/Query/输入长度时明确重启受影响的过程；暂停时允许沿记录下钻，再回来继续。
- 必须能逐步复现，支持减少动效偏好；移动端仍保留原图组织，不用缩小到无法读数的动画。

## 验收重点

新阶段必须由真实数据依赖定义；未完成阶段不能产出已提交结果；读取不会删除未选中的缓存；共享读取不产生副本；完整一轮结束才推进Token；各算法拥有真实阶段图。先验证单次过程，再扩展连续位置和跨会话生命周期。
